# 관리자 문의함과 페이지 문구

## 문의 방식

최신 요청에 따라 이메일 자동 발송을 사용하지 않고 웹사이트 양식을 관리자 문의함에 저장합니다. `/admin` 로그인 → 문의함에서 내용/이름/회신 이메일/접수 시각을 확인하고 새 문의·확인 중·처리 완료 상태와 내부 메모를 관리합니다. 목록은 최신순 50건씩 표시하며 새로고침 버튼으로 갱신합니다. 상태 변경은 고객에게 메시지를 발송하지 않습니다.

새 빈 Supabase 프로젝트: `install-new-project.sql` 한 번 실행.
기존 프로젝트: `inbox-and-copy.sql`만 추가 실행. 이미 적용된 파일을 중복 실행하지 않습니다.

서버 설정: `INQUIRY_PROVIDER=database`, `NEXT_PUBLIC_SUPABASE_URL`, **서버 전용** `SUPABASE_SERVICE_ROLE_KEY`, 기존 Upstash 요청 제한 설정, 개인정보 버전이 필요합니다. service_role 키에 NEXT_PUBLIC 접두사를 붙이거나 채팅/Git에 공유하면 안 됩니다. 공개 브라우저에는 publishable key만 사용합니다.

정식 서버는 Vercel의 `preview/website-mvp` 브랜치입니다. GitHub Pages 정적 미리보기에는 API가 없습니다. 실제 테스트 저장→관리자 조회→익명/비관리자 읽기 및 직접 쓰기 거부→개인정보 고지 확정 후 `INQUIRY_DELIVERY_VERIFIED=true`, site.inquiriesEnabled 및 site.legalApproved를 활성화합니다. 현재 실제 저장은 미연결이며 입력창을 활성화하거나 접수 완료를 가장하지 않습니다.

## 페이지 문구

`/admin` → 페이지 문구 → 분류 또는 검색 → 수정할 문구 선택 → 수정 → 초안 저장 → 공개 반영. 새 고객 페이지를 열어 확인합니다. 공개값은 4분마다 갱신하며 로딩 실패 시 정적 기본값을 유지합니다. `기본 문구로 복원`은 해당 초안과 공개값을 삭제합니다. 같은 원문을 쓰는 위치는 함께 바뀝니다.

홈·클래스·작업·스튜디오·소개·후기·문의·법적 안내·404 및 공통 메뉴/푸터의 기본 문구를 편집합니다. 수업별 기수/가격/커리큘럼, 등록 후기, Instagram 소개는 기존 관리 메뉴에서 수정합니다. 중요한 가격과 일정은 해당 수업 관리에서 편집하는 것이 좋습니다.

한계: 검색 결과 제목/OG 등 초기 metadata는 기존 코드 기준입니다. 이미지 내부의 글자와 영상 음성은 원본 파일을 바꿔야 합니다. 외부 설문 HTML·Instagram 자체 게시물, 관리자 UI와 운영상 오류 메시지는 일반 페이지 문구 편집 대상이 아닙니다. 링크 주소/레이아웃을 문구 편집으로 변경하지 않습니다. 문구를 HTML로 입력해도 코드로 실행하지 않습니다.

문구 변경으로 법적 동의가 완료되거나 문의가 자동 활성화되지는 않습니다. 저장소 미연결 관리자는 문구 선택/입력 미리보기만 가능하며 저장·공개가 되지 않는다고 표시합니다.

## 검증 기록

단위/API 테스트 44개 통과. 모의 저장소로 문의 상태/내부 메모 저장, 문구 초안 격리→공개 반영→HTML 문자열의 안전한 표시→원문 복원 확인. 11개 경로 × 390px/1440px의 22개 화면에서 JS 오류·가로 넘침 없음 및 axe WCAG 자동 검출 0. reduced-motion과 JavaScript 비활성 콘텐츠도 확인. 실제 Supabase 저장/RLS 및 운영 접수 E2E는 계정 연결 후 검증해야 합니다.
