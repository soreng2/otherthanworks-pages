# 운영자 후기 관리

## 수업 상세페이지 관리 추가

`/admin`에 로그인한 뒤 수업을 선택하고 소개·기수·기간·수강료·일정·커리큘럼을 수정할 수 있다. 사진은 여러 장 업로드·순서 이동·페이지에서 제외가 가능하다. ‘초안 저장’은 공개 화면을 바꾸지 않으며 ‘공개 페이지에 반영’이 별도 공개 레코드를 갱신한다. 홈페이지와 클래스 목록도 공개된 수업명·소개·기수를 불러온다.

`supabase/reviews.sql` 다음에 `supabase/courses.sql`을 실행한다. 비로그인 이용자는 published 레코드와 연결 사진만 읽고 관리자만 draft 읽기/쓰기가 가능하다. 브라우저 키는 publishable key이며 권한은 SQL RLS에서 강제한다. 운영 전에 실제 비관리자 토큰과 익명으로 직접 API를 호출해 이 정책을 검증한다.

상세페이지 사진은 폭 최대1600px/높이최대12000px JPEG로 재인코딩한다. 긴 이미지의 가독성을 위해 여러 장으로 나누는 것을 권장한다. 초안에서 제외된 사진은 즉시 영구 삭제하지 않아 기존 공개 페이지와 복구 가능성을 보존한다. 저장하지 않고 이탈한 사진은 저장소에 남을 수 있으며 운영자가 주기적으로 참조 여부를 확인해 정리해야 한다.

관리자에서 사진 설명을 입력해야 공개할 수 있다. 이미지에만 중요한 가격·커리큘럼을 넣지 말고 텍스트 항목에도 입력한다. 공개 페이지 HTML metadata는 기본 콘텐츠 기준이고, 브라우저 화면은 저장소의 최신 콘텐츠를 조회한다. 수업명 변경 시 검색 결과 제목까지 즉시 갱신하는 서버 렌더링은 후속 작업이다. 현재 관리자에서 기존 5개 수업을 편집할 수 있고 새 경로의 수업 추가는 코드 작업이 필요하다.

## 스마트스토어 결제

2026-10-20 사용자 최종 지정으로 스토어 홈 `https://smartstore.naver.com/monmut`를 공통 수업 선택 링크로 제공한다. 개별 상품을 아직 등록하지 않았어도 ‘스마트스토어에서 수업 선택하기’로 홈을 열 수 있다. 이는 특정 수업의 판매/결제 완료 확인이 아니다. 아래 개별 상품 관리 기능은 선택적으로 사용할 수 있다.

운영자의 최종 선택은 monmut 스마트스토어 외부 결제이다. 각 수업 상품의 `https://smartstore.naver.com/monmut/products/숫자` 주소를 입력하고 수업·기수·가격·판매 상태·환불 안내 확인 체크 후 공개 반영한다. 다른 도메인, 스토어 홈, 타 판매자 링크, 쿼리/스크립트 URL은 거부한다. 공유용 주소에 쿼리가 있으면 상품 본문 주소를 사용한다.

등록된 URL 형식 검사와 운영자의 확인은 실제 구매 테스트를 대체하지 않는다. 실상품 페이지 열기·모바일 전환·주문/취소는 연결 후 별도 확인해야 한다. 이 홈페이지에서는 결제 성공이나 수강 등록 완료를 표시하지 않는다. 주문 확인·취소·환불은 스마트스토어 판매자센터에서 관리한다.

## 계정 연결을 위한 사용자 경로

- Vercel: https://vercel.com/new 에서 GitHub로 로그인 → `soreng2/otherthanworks-pages` 가져오기 → 실제 Next.js 소스인 `preview/website-mvp` 브랜치 선택. 기본 main을 그대로 배포하면 기존 설문이 배포된다. 브랜치 선택이 보이지 않으면 프로젝트 Settings → Environments 또는 Git의 Production Branch에서 지정한 뒤 해당 브랜치 재배포. 프로젝트 UI에 따라 메뉴 위치가 다를 수 있다.
- Supabase: https://supabase.com/dashboard 에서 운영자 계정으로 프로젝트 생성. SQL 실행·관리자 사용자 등록·Vercel 공개 환경변수 입력 후 재배포. 실제 비밀번호·DB비밀번호·secret/service_role 키는 채팅으로 공유하지 않는다.
- 가비아: https://my.gabia.com/service 에서 DNS 관리툴 → otherthanworks.com → DNS 설정. Vercel Domains에 루트/www 추가 후 제공되는 프로젝트별 레코드로 변경. 현재 관리 접근이 없으므로 이 문서는 DNS 값 변경이나 SSL 발급 완료를 뜻하지 않는다.

구현 경로: `/admin` 운영자 로그인·사진/글 등록·공개/비공개, `/reviews` 공개 후기 목록.
현재 외부 프로젝트와 운영자 계정이 없어 실제 저장 및 권한 E2E는 미검증이다. 정적 미리보기에서도 계정 미연결 상태를 명시하며 저장 완료를 가장하지 않는다.
로컬 검증: lint·TypeScript·프로덕션 빌드 통과, 기존 문의 테스트 30개 통과. `/admin`·`/reviews` 390px/1440px 응답·가로 넘침·브라우저 오류 및 미연결 안내 확인. 실제 Chromium에서 SVG·10MB 초과·잘못된 이미지 거부 및 PNG→2000×1000 JPEG 변환 확인. 이 결과는 실제 DB/Storage 권한 검증을 대체하지 않는다.
운영자 확정 내용을 반영해 수업 목록·상세를 업데이트했고 푸터에 후기 및 운영자 관리 링크를 추가했다.

추가 검증: 수업 정보/상품 URL/사진 경로 검증 포함 단위 테스트 총34개 통과. 모의 Supabase 응답을 사용하는 실제 브라우저에서 비관리자 거부, 사진 등록, 초안의 공개본 격리, 공개 반영 후 수업명/사진/결제 링크 조회 및 모바일 가로 넘침을 확인했다. 이 모의 검증은 원격 SQL 정책이나 실제 결제 검증을 의미하지 않는다.

## 연결

1. 운영자 소유 Supabase 프로젝트 생성 후 SQL Editor에서 `supabase/reviews.sql`을 한 번 실행한다. 기존 테이블/정책이 있는 프로젝트라면 먼저 충돌을 검토한다.
2. Auth의 공개 회원가입을 끄고 운영자 사용자를 생성한다. 대시보드에서 확인한 사용자의 UUID를 `public.review_admins.user_id`에 등록한다. 이메일 문자열이나 브라우저 상태만으로 관리자 권한을 부여하지 않는다.
3. 배포 환경에 `NEXT_PUBLIC_SUPABASE_URL`과 공개 publishable key를 설정하고 다시 빌드한다. service_role 또는 secret key는 사용하지 않는다. 실제 비밀번호는 채팅이나 Git에 보관하지 않는다.
4. `/admin`에서 로그인, 사진 선택, 제목·후기·사진 설명 입력, 공개 동의 확인, 비공개 저장 → 미리보기 확인 → 공개하기 순서로 사용한다. 브라우저를 새로 열면 다시 로그인한다.
5. `/reviews`에서 게시물이 조회되는지 다른 브라우저로 확인한다. 운영자/비운영자/비로그인으로 DB와 Storage API 직접 호출도 시험한다.

## 보안과 검증 범위

- DB RLS와 Storage RLS가 실제 쓰기 권한을 검사한다. 관리 화면 노출 여부는 권한 제어 수단이 아니다.
- 비공개 버킷. 익명 이용자는 공개·동의가 모두 true인 후기 및 연결된 사진만 읽는다. 사진 URL은 5분 만료이며 비공개 전환 전 발급된 URL은 남은 유효시간 동안 열릴 수 있다.
- 사진은 최대 10MB, JPEG/PNG/WebP 입력을 브라우저에서 디코딩 후 최대 2000px JPEG로 변환해 EXIF를 제거한다. 저장소도 JPEG와 크기 제한을 적용한다. SVG/HTML은 받지 않는다.
- 본문은 React 텍스트로 출력하며 HTML 실행을 허용하지 않는다. 등록 실패를 성공으로 표시하지 않는다.
- 공개 계정 생성 금지, 비관리자 쓰기 거부, 비공개 사진 익명 조회 거부, 업로드 실패/만료 로그인, 실제 저장 후 재접속·공개·비공개 전환을 운영 전 검증해야 한다.
- 이 구현은 신규 등록과 공개 전환을 제공한다. 기존 글 수정·영구 삭제·사진 교체는 아직 관리 화면에 없다. 잘못 올린 글은 비공개 후 다시 등록할 수 있다.

## 도메인 배포

목표는 `www.otherthanworks.com`. 현재 공개 미리보기는 GitHub Pages의 `/preview/` 경로이며 Vercel 배포가 아니다.
루트의 기존 설문을 보존하려면 GitHub Pages에 도메인을 바로 덮어 연결하지 않는다.
Vercel에 `soreng2/otherthanworks-pages`를 연결하고 Next.js 소스가 있는 `preview/website-mvp` 브랜치를 선택한다. 현재 main은 기존 설문 + 정적 미리보기이므로 잘못된 브랜치를 배포하지 않는다.
프레임워크 Next.js, 프로젝트 루트 `.`; 환경 변수를 넣고 먼저 Preview URL에서 확인한다.
Domains에 루트와 www를 추가하고 www를 대표 도메인으로 설정한다. 가비아 DNS 관리에서 Vercel이 해당 프로젝트에 실제 제시한 레코드만 적용한다. MX/TXT 및 기존 메일 레코드를 보존한다.
현재 환경에 Vercel·가비아 계정 접근 수단이 없고 DNS 조회도 네트워크 제한으로 실패했으므로 레코드와 SSL 상태는 확인되지 않았다. 추측한 IP를 안내하거나 연결 완료로 처리하지 않는다.
